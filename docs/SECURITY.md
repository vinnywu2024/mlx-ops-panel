# 安全模型与已知限制

## 前提：这是一个「本机工具」，不是「服务」

面板没有账号、没有登录、没有 TLS、没有鉴权。它安全的**全部前提**是只监听 `127.0.0.1`，且只有本机的可信用户在操作。请勿：

- 把 `HOST` 改成 `0.0.0.0`（代码里它是常量，刻意不提供配置开关）；
- 用 nginx / Caddy / SSH 端口转发把它暴露到局域网或公网；
- 在有不可信本地用户的机器上运行，还把白名单动作指向高权限命令。

## 已实现的防护

| 风险 | 措施 |
| --- | --- |
| 局域网访问 | 只绑 `127.0.0.1`；`Host` 头白名单（仅 `127.0.0.1` / `localhost` / `::1`） |
| 命令注入 | 服务端固定 argv 白名单，浏览器只传 key；`shell=False`；不拼 shell |
| 跨站触发（CSRF） | 所有 POST 校验 `Origin`（存在时必须为本面板）+ 进程内一次性 token；token 用 `secrets.token_urlsafe(24)` 每次启动重新生成，只注入本机页面 HTML，跨站页面受同源策略限制读不到 |
| 恶意请求体 | `Content-Length` 上限 64 KiB，实际只读前 4096 字节；非 JSON / 非 dict 一律 400/403 |
| XSS | 页面所有动态字段经 `esc()` 转义后再写 `innerHTML` |
| DNS rebinding | Host 头校验拒绝非回环域名 |
| 误关面板 | 关闭需二次确认 + token；`panel.sh stop` 会核对 PID 对应的进程命令行，拒绝停掉占用同端口的其他进程 |
| 响应丢失 | `/api/stop` 先 flush 200，再由独立线程延迟 `shutdown()` |
| 信息外泄 | 审计日志只记输出前 200 字符；不读取模型权重与对话正文；面板不发任何外部网络请求 |

## 已知限制（不打算在本版本解决）

1. **本机任意进程都能调用 API**。同机上的恶意程序可以直接请求 `127.0.0.1` 读页面拿 token，然后触发白名单动作。这个威胁模型下没有意义做防护——能读到本机页面的进程已经很强了。
2. **白名单动作仍有副作用**。`restart` 会清空 KV 与 prompt cache、短暂中断服务；`selftest` 会真的发测试请求。所以它们带二次确认，且**不提供 stop / switch / 改配置**。
3. **`lsof` 输出的命令行片段可能包含敏感参数**。「监听端口全览」会展示其他进程命令行前 150 字符。若本机有进程把密钥写在命令行里，面板会照实显示——这也是不暴露面板的另一个理由。
4. **服务识别靠字符串猜**，可能不准，仅供快速定位，不能当作安全审计结论。
5. **没有限流**。本地使用量很小，但若被同机程序刷 `/api/status`（每次都跑 `lsof` + `pgrep`），会造成 CPU 抖动。
6. **日志与配置以明文读取**，没有沙箱隔离；面板进程权限等同于启动它的用户。建议用普通用户启动，不要 sudo。
